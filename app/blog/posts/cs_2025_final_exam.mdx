### 2번. 파이프라인(Pipeline)

- **개념:** 하나의 명령어가 실행되는 동안 다음 명령어의 인출이나 해독을 동시에 진행하는 **병렬 처리** 기술입니다.
- **성능 향상:** 명령어 처리 단계를 겹쳐서 수행함으로써 단위 시간당 처리량(Throughput)을 늘려 CPU 전체 성능을 향상시킵니다.

## 2. 캐시 메모리 (문제 4~5)

### 4번. Associative Memory

주소값이 아닌 **데이터의 내용(Content)**의 일부를 검색 키로 사용하여 데이터를 직접 찾는 방식입니다. 이를 통해 캐시 내에서 원하는 데이터가 있는지 빠르게 확인할 수 있습니다.

### 5번. Hit Ratio

CPU가 요청한 데이터가 캐시 메모리에 존재할 확률입니다. 이 비율이 높을수록 속도가 느린 주기억장치(RAM)에 접근하는 횟수가 줄어들어 전체 시스템 속도가 비약적으로 빨라집니다.

## 3. Pep/8 기계어 및 어셈블리어 실습 (문제 6~12)

### 6번. 입출력 기계어 완성

- C 코드의 `scanf("%c", &ch1)`는 기계어 `49 00 20` (CHARI 0x0020, d)입니다.
- `printf("%c", ch1)`에 해당하는 기계어는 **`51 00 20`** (CHARO 0x0020, d)이고, `ch2`는 **`51 00 21`**입니다.
- 마지막은 프로그램 종료인 **`00`** (STOP)과 데이터 끝을 알리는 **`zz`**가 들어갑니다.

### 10번. 덧셈 프로그램 빈칸

```asm
bonus:  .EQUATE 10      ; 상수 정의
        STA     sum, d   ; 더한 결과를 sum 변수에 저장
        DECO    sum, d   ; 결과값을 숫자로 출력
```

### 11번. While 루프 빈칸

```asm
while:  DECI    input, d
        LDA     input, d   ; 입력받은 값을 검사하기 위해 로드
        CPA     0, i
        BREQ    endWhile   ; if (input == 0) break
        ; ... 반복 본문 ...
        BR      while      ; 루프 끝에서 다시 처음으로
endWhile:
```

### 12번. 대문자 판별(IF 조건문) 빈칸

`ch >= 'A'` 조건 통과 후 `ch <= 'Z'`를 검사하기 위해 다시 값을 가져옵니다.

```asm
        LDBYTEA ch, d      ; ch 값을 다시 로드
        CPA     'Z', i
        BRGT    else       ; Z보다 크면 else로 이동
```

## 4. 심화 문제 (문제 8~9)

### 8번. 코드 해독

- `D1 00 1D` (LDBYTEA 0x001D, d): 주소 0x001D에서 바이트를 로드합니다.
- 이후 연산(`C1`, `71`, `A1` 등)을 거쳐 최종적으로 `51 00 16`을 통해 결과값을 문자로 출력합니다.
- 자료에 따르면 0x0016 위치에 결과가 저장됩니다.

### 9번. % 연산 아이디어

`number % 2 == 0`은 짝수인지 확인하는 것입니다. Pep/8에서는 **`ANDA 1, i`** (1과 비트 단위 AND 연산)를 수행한 결과가 0이면 짝수, 1이면 홀수임을 이용하여 `BREQ`나 `BRNE`로 분기할 수 있습니다.
